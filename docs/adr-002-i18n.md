# ADR-002 — Internationalization: string ids + community catalogs

Status: Final (user-accepted 2026-10-25; v1-spec reopen authorized by user).
Decision: D-023.

## Decision

Strengthen the seg-09 §11 hook into a frozen design so v2 translation needs
no refactor (the existing MUST, now testable). English-only v1; translation
infrastructure + first community catalogs in v2 (no committed language —
Slovak (`sk`), user-supplied, is the expected first catalog, best-effort and
non-blocking for v2).

- String ids: every user-visible string lives in the `strings` module under
  a STABLE id (Notepad++ `nativeLang` precedent: ids map UI pieces to text;
  ids never change meaning — rename = new id + ADR note). Zero inline
  literals in views (v1 rule, enforced by T-910). ICU-style placeholders;
  no string concatenation for sentences.
- Catalogs: one versioned file per locale, pinned to a string-id-set
  version. Format decided at v2 implementation (VERIFY against the seg-02 §3
  M-11 license/maintenance criteria); requirements: BCP-47 tags, CLDR plural
  rules, RTL-safe layout support, per-key fallback. English ships in-tree.
- Fallback chain: `ui.locale` → `ui.fallback_locale` → `en`. Missing key =
  English text + coverage counter (never blank, never crash).
- Locale detection: OS locale at first run seeds `ui.locale`; user override
  in config (General tab, v2). Date/number formatting follows the OS locale
  (mechanism = VERIFY at v2 implementation).
- Community flow: catalog contributions arrive as PRs carrying translator,
  id-set version, and coverage %; CI checks id-set match + placeholder
  consistency. No community catalog ever blocks a release.
- Plugin strings (ADR-001): namespaced `<plugin-id>.<key>`, shipped by the
  plugin, same fallback chain; untranslated plugin = English plugin strings.

## Reason

v1 English-only keeps scope contained while the id freeze makes v2 purely
additive. Notepad++ validates the community model (reference English file,
id-keyed translations, in-app selector, PR contributions) at zero infra cost,
fitting D-018.

## Non-goals

No v1 translations; no machine-translation pipeline; no per-clip content
translation (UI chrome only); no committed v2 language list.

## Affected segments

seg-00 (D-023, glossary), seg-01 (F-803, §8, milestones), seg-03 (config
keys), seg-09 (§11 full design, §4 Localization control, T-910/911),
seg-12 (catalog packaging), plan.md (step 8). (No seg-02 change: the §5/§15
no-payload logging rules already cover localized output.)

## Migration / test impact

None pre-v1. Tests: T-910 `[unit]` v1 strings-module conformance (no inline
literals, every id has English text); T-911 `[unit]` v2 locale fallback +
plural vectors + catalog conformance. Post-v1, string-id-set bumps are
additive; id removals/renames need a new ADR.
