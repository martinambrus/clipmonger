# Privacy

Clipmonger records what you copy. This page explains what it leaves out, how
to stop it recording, and where your data goes.

## Your data stays on your computer

Clipmonger has no network code. It does not send clips, settings or usage data
anywhere, and it does not check for updates.

- History, permanent clips and settings are stored in a local SQLite database
  and files in your profile folder.
- The Clipmonger UI, the background daemon, the command line tool and the
  GNOME extension talk to each other over a local channel (a Unix socket on
  Linux and macOS, a named pipe on Windows) protected by a token stored in the
  profile folder.

The profile folder is:

| Platform | Profile folder |
|---|---|
| Windows (installer) | `%APPDATA%\clipmonger` |
| Windows (portable ZIP) | The folder you extracted Clipmonger into |
| Linux | `~/.local/share/clipmonger` |
| macOS | `~/Library/Application Support/clipmonger` |

Anyone who can read this folder can read your history. Backups you create
contain your history too. See [Backup and data](backup-and-data.md).

Settings has a **Check for updates** option, but no update check exists yet;
it has no effect. Syncing between devices is not available.

## Signals from other applications

Password managers and similar programs can mark what they copy as private.
Clipmonger honours these marks where the operating system provides them. A
marked copy is not stored at all: no row, no preview, no thumbnail. Clipmonger
only counts that a copy was skipped.

| Platform | Marks honoured |
|---|---|
| Windows | `ExcludeClipboardContentFromMonitorProcessing`, `Clipboard Viewer Ignore`, and `CanIncludeInClipboardHistory` or `CanUploadToCloudClipboard` set to 0 |
| macOS | `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` |
| Linux (X11, Wayland and the GNOME extension) | `x-kde-passwordManagerHint` |

Not every password manager sets these marks. For those that don't, add them
to the denylist.

## Denylist of applications

Copies made in an application on the denylist are never stored.

1. Open Settings, **Privacy** tab.
2. Add the application to **Privacy denylist**.
3. Click **Apply**.

**Monitor ignored apps** on the History tab works the same way; Clipmonger
uses both lists together.

How an entry is matched depends on the platform:

| Platform | Matched against | Rule |
|---|---|---|
| Windows | The executable of the program that owns the clipboard | Case-insensitive, entry may be part of the name (`keepass` matches `KeePass.exe`) |
| macOS | The frontmost app's bundle id or name | Case-insensitive, entry may be part of it (`1password` matches `com.1password.1password`) |
| X11 desktops | The window class of the window that owns the clipboard | Case-insensitive, entry may be part of it |
| GNOME (extension) | The focused app's id, window class or executable | Whole id, case-insensitive; a `.desktop` suffix is ignored (`org.keepassxc.KeePassXC`) |

On Wayland desktops other than GNOME, the system does not tell applications
which program copied something, so the denylist cannot be applied there. Rely
on the password manager's mark, pause monitoring, or use strict privacy mode.

## Strict privacy mode

Turn on **Privacy strict mode** (Settings, **Privacy** tab) to record less:

- Only plain text is stored. Images, file lists and formatted text are
  skipped; a copy that has plain text alongside other formats is stored as
  plain text only.
- The history limits are halved: **History maximum items**, **History maximum
  store bytes** and **History retention days** (when set) count for half
  their value.

Strict mode does not remove clips that are already stored, except when the
halved limits push old ones out. Pinned clips are kept.

## Pausing monitoring

While monitoring is paused, nothing you copy is recorded. The popup shows
**Monitoring paused** and the tray icon tooltip shows **Paused**. Pasting
from the history still works.

| How | Pause | Resume |
|---|---|---|
| Tray menu | **Pause monitoring** | **Resume monitoring** |
| Tray menu, for a while | **Pause for one hour** (resumes by itself after an hour) | **Resume monitoring** |
| Command line | `clipmonger-cli --profile-dir <profile> toggle-monitor` | The same command again |
| Scroll Lock key (Windows only) | Press Scroll Lock | Press Scroll Lock again |

The Scroll Lock toggle is off by default. Turn on **Toggle monitoring with
Scroll Lock** in Settings, History tab. It works on Windows only; on Linux the
option is shown but has no effect. Some keyboards have no Scroll Lock key.

## Other settings that affect what is recorded

All on the History tab of Settings:

- **Monitor formats**: which kinds of content are recorded.
- **Monitor maximum bytes**: larger copies are not stored. They appear in the
  popup as a **Too large — not saved** row that names the formats, without
  their content.
- **Capture primary selection** (Linux only): also record text you select
  with the mouse, not only what you copy.
- **History retention days**, **History maximum items** and **History maximum
  store bytes**: how long and how much history is kept.

See [Settings](settings.md).

## Removing clips

- Delete a single clip in the popup with **Delete** or **Delete entry**. This
  hides it at once; **Purge removed clips** (Settings) or
  `clipmonger-cli --profile-dir <profile> purge-removed` removes deleted
  clips from the database for good.
- To remove everything, quit Clipmonger and delete the profile folder. On
  macOS, `clipmonger-cli --profile-dir ~/Library/Application\ Support/clipmonger
  uninstall --delete-history` does this for you.

See [Backup and data](backup-and-data.md).

## macOS: clipboard privacy setting

On macOS 15.4 and newer, macOS lets you control which apps may read the
clipboard. If Clipmonger is not set to **Always allow** in System Settings,
Privacy & Security, **Paste from Other Apps**:

- set to ask, macOS may prompt you when Clipmonger reads the clipboard;
- set to deny, Clipmonger cannot read the clipboard and records nothing.

Set it to **Always allow** for Clipmonger to record your history. See
[Getting started on macOS](getting-started-macos.md).
